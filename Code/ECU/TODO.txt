 2. LAYOUT DE LAS TRAMAS CAN
------------------------------------------------------------
Falta: definir en equipo el orden de bytes, escalas y
endianness de cada mensaje. Es el pendiente que mas cosas
desbloquea: hasta que no este, ningun handler puede parsear.

Definicion de cada ID (include/can_ids.h):

  [ ] can_ids.h:29   0x080 FAULT / emergencia
                     Minimo: nodo origen, codigo de falla y nivel.
  [ ] can_ids.h:37   0x100 Estado ECU + heartbeat
                     Minimo: estado, contador y flags de sensores.
  [ ] can_ids.h:45   0x180 APPS + BSE
                     Las dos señales de APPS por separado (el chequeo
                     de implausibilidad las necesita crudas) + freno.
  [ ] can_ids.h:54   0x200 RPM ruedas delanteras
                     Dos ruedas por trama, unidad y escala.
  [ ] can_ids.h:62   0x201 RPM ruedas traseras
                     Mismo formato que 0x200.
  [ ] can_ids.h:69   0x280 Volante
                     Que botones entran, incluido el de RTD.
  [ ] can_ids.h:85   0x380 BMS / bateria
                     Minimo: tension de pack, corriente, temperatura
                     maxima de celda y estado del AIR.
  [ ] can_ids.h:93   0x400 IMU
                     Tres ejes de cada sensor no entran en 8 bytes con
                     buena resolucion: partir en dos tramas o recortar.
  [ ] can_ids.h:101  0x500 TPMS
                     Una trama por rueda, o una sola con indice.

  (0x300 Driver / inversor: ver grupo 4.)
